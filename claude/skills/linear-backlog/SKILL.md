# 할 일을 Linear Backlog 이슈로 만들기

## 1. 항목 정리

요청에서 할 일마다 아래를 뽑는다.

- **할 일**: 무엇을 할지. 이슈 제목이 된다. 짧은 한 줄.
- **배경 / 목적**: 왜 하는지. 둘 중 하나 이상 반드시 있어야 한다.
  - 배경: 이 일이 생긴 계기, 상황
  - 목적: 끝나면 얻는 것
- **세부 할 일, 완료 조건**: 사용자가 말했거나 대화에서 정해진 것만 적는다. 없으면 적지 않는다.

## 2. 배경, 목적이 없으면 묻는다

- 사용자가 직접 말한 내용과 대화에서 정해진 내용만 쓴다. 할 일 문구에서 배경, 목적을 추측하거나 지어내지 않는다.
- 배경과 목적이 둘 다 없는 항목은 이슈를 만들기 전에 AskUserQuestion으로 묻는다.
  - 여러 항목이 비어 있으면 한 번에 모아서 묻는다(항목당 질문 하나, 최대 4개).
  - 대화 맥락에서 그럴듯한 후보가 보이면 선택지로 제시한다. 사용자는 "Other"로 직접 적을 수 있다.
- 답을 받을 때까지 그 항목은 만들지 않는다. 배경, 목적이 있는 항목은 먼저 만들어도 된다.

## 3. 어디에 만들지 정한다

- 팀: `ai-team`.
- 프로젝트: 대화가 특정 Linear 프로젝트의 작업이면 그 프로젝트에 넣는다(예: 지금 다루는 이슈가 속한 프로젝트). 정할 수 없으면 `AI Team Backlog`에 넣는다.
- 상태: `Backlog`. 담당: `me`.
- 대화가 특정 이슈에서 나온 할 일이면 그 이슈를 `relatedTo`로 연결한다.

## 4. 중복 확인

만들기 전에 `list_issues`로 제목의 핵심 단어를 검색한다. 같은 할 일이 이미 열려 있으면 만들지 말고 사용자에게 그 이슈를 알린다.

## 5. 이슈 본문 형식

```
## 배경

<배경과 목적. 있는 것만>

## 할 일

- [ ] <세부 할 일. 있을 때만>

## 완료 조건

<있을 때만>
```

- 한국어로 쓰고, 산문은 종결어미로 끝낸다.
- 근거가 되는 레포 문서가 있으면 경로를 적는다. 외부 자료는 링크로 붙인다.

## 6. 보고

만든 이슈의 번호, 제목, 링크를 한두 줄로 알린다.

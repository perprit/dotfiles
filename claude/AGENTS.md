# AGENTS.md: 전역 규칙

## 구현 범위

- 사용자가 명시적으로 지시하지 않은 디테일은 절대 구현에 포함하지 않는다.
- 요청하지 않은 푸터, 슬로건, 홍보 문구, 설명 문구, 장식 요소, 추가 UI 또는 기능을 임의로 만들거나 넣지 않는다. 예: “작은 한 방. 커다란 연쇄.” 같은 푸터.
- 완성도, 미관, 관례를 이유로 요청 범위를 확장하지 않는다. 미지정된 선택적 요소는 생략한다.
- 요청한 기능을 작동시키는 데 필요한 내부 구현은 수행하되, 이를 근거로 사용자에게 보이는 디테일을 추가하지 않는다.

## 툴 설정 파일

- 툴 설정(kitty, nvim, herdr, karabiner, zed 등)을 확인하거나 바꿀 때는 먼저 dotfiles 저장소(`${DOTFILES:-$HOME/dotfiles}`)를 참고한다. 저장소의 `AGENTS.md`와 각 폴더 README의 절차를 따른다.
- `~/.config/...`는 dotfiles를 가리키는 심볼릭 링크다. 설정은 저장소 안의 파일을 고친다. 링크가 일반 파일로 바뀌어 있으면 내용을 저장소로 옮기고 다시 링크한다.
- dotfiles에 아직 없는 툴의 설정을 만들거나 바꾸면 저장소에 추가하는 것을 제안한다.

## 글쓰기

- em dash, 중간점(·) 사용하지 않음. 중간점 대신 쉼표(,) 사용.
- em dash 이후에 따라오는 비유/설명문 사용하지 않음. (사실은 이렇다, A가 아니다, B다)
- 출력 토큰은 귀중하므로 간결하게 답한다.
- ASD-STE100(간소화 기술 표현) 원칙 중 한국어에 맞는 것을 따른다. 영어 전용인 승인 단어 사전과 문법 규칙(관사, 시제, -ing)은 적용하지 않는다.
  - 한 단어는 한 뜻으로 쓴다. 같은 대상은 같은 용어로 부른다.
  - 문장은 짧게 쓴다. 절차문은 한 문장 50자 안팎, 설명문은 60자 안팎이다.
  - 한 문장에 한 주제만 쓴다. 원인과 결과는 한 주제로 보고 한 문장에 둘 수 있다.
  - 관련된 문장은 연결어로 잇는다. 문장을 나눠도 연결어는 지우지 않는다. 관계마다 연결어를 하나로 고정한다(결과: 그래서, 이유: ~때문이다, 대조: 그러나/~지만).
  - 설명 문단은 첫 문장에 주제를 쓴다. 뒤 문장은 그 근거나 세부다.
  - 절차는 명령형으로 쓰고, 한 문장에 지시 하나만 쓴다.
  - 명사를 길게 잇지 않는다(3개 이하).
  - 문장은 "~다"로 끝내지 않고 구 형식으로 끝낸다. 뜻이 같고 읽기 쉬우면 짧은 형태를 쓴다. 줄이려고 조사를 빼서 명사를 잇지 않는다.
  - 핵심을 먼저 쓰고, 이유와 세부는 뒤에 쓴다.
  - 경고와 주의는 위험을 먼저 쓰고, 이유를 다음에 쓴다.
